# Threat model

Update when architecture or exposure changes.

| Asset | Actor | Entry point | Trust boundary | Abuse case | Mitigation | Residual risk |
| --- | --- | --- | --- | --- | --- | --- |
| Hinge session header (bearer-equivalent) | Malware/other local process on the member's machine | Session file on disk / env var / password-manager process | OS file permissions and OS process boundary | Local process reads the session file and impersonates the member to Hinge | File written mode 0600, directory 0700 (`session-store.ts`); `HINGE_SESSION_REF` keeps the secret out of the filesystem entirely, resolved on demand via the member's password manager | Mode bits are a no-op on Windows (relies on per-user `%APPDATA%` ACL instead) — documented, not yet hardened to the OS credential store |
| Hinge session header | Shoulder-surfing / shell history / CI logs | `hinge secret <ref>`, error messages | CLI output boundary | Secret value printed to stdout/stderr or committed to logs | `secret` command reports length only, never the value; `api.ts` error paths are built to never interpolate the header | None known; relies on no future code path echoing the header — worth a lint rule if the codebase grows |
| Captured session file | The member, during capture | `tools/hinge_token.py` output file | Local filesystem | File left on disk after import, later committed or backed up | `hinge auth import` deletes the source file by default (`--keep` opts out); documented cleanup steps in `docs/auth.md` | Depends on the member actually using `auth import` rather than hand-copying the header elsewhere |
| Other Hinge members' data | The CLI author, during API reverse-engineering | mitmproxy capture of the member's own app traffic | Hinge's platform boundary | Capture incidentally includes another member's profile/message content relayed through the member's own session | Captures were deleted after use; `docs/api-inventory.md` records only endpoints/headers/ordering, no bodies, tokens or third-party content | None for past captures (deleted); future captures must follow the same discipline — not yet enforced by tooling, only by process |
| Hinge's production API | This project's own CI | GitHub Actions runners | Network boundary to a third party | An automated "pentest" workflow sends attack traffic to Hinge's live infrastructure | No such job exists; `security.yml` explicitly scopes to static/dependency scanning instead (see comment at the top of that file) | None — this is a closed decision, not a residual risk |
| npm dependencies | Supply chain | `package.json` / lockfile | Build boundary | A compromised or vulnerable transitive dependency ships in a release | Dependabot (npm + actions, weekly), `npm audit --audit-level=high` in CI, CodeQL static analysis | Standard supply-chain residual risk; mitigated, not eliminated |
