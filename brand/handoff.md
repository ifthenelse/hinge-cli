# Handoff: hinge-cli brand assets

Adapted from the design-handoff template to what actually applies to a CLI tool's identity: there is no
screen layout, so breakpoints/hover states/animation sections are replaced with the real equivalents —
terminal colour support and file selection by output context — rather than left as invented placeholders.

## Overview
The logo kit (symbol, small-size cut, lockup, favicon/icon set) ships for: the README header, a future
`--help`/banner output, the GitHub repo's social preview and favicon, and any packaging (npm page, Homebrew
tap) that shows an icon. No in-app UI exists to hand off; this is the entire surface.

## Design tokens used
| Token | Value | Usage |
| --- | --- | --- |
| `color-ink` | `#111111` | Default mark colour on light backgrounds |
| `color-brand` | `#2563EB` | App-icon fill / accent only, never the default mark colour |
| `color-white` | `#FFFFFF` | Mark on dark backgrounds |
| `clear-space` | 1 × symbol height | Minimum space around the mark in any placement |

## Assets (components)
| File | Variant | Use | Notes |
| --- | --- | --- | --- |
| `assets/mark.svg` | symbol, with pin hole | ≥24 px, anywhere scalable | Square viewBox 256×256 |
| `assets/mark-small.svg` | symbol, no pin hole | <24 px (favicons, inline terminal icons) | The hole closes below 24 px; use this cut instead of scaling `mark.svg` down |
| `assets/lockup.svg` | symbol + wordmark | README header, social banner | Wordmark is outlined to paths — do not retype it in a font |
| `assets/favicon.ico`, `assets/icon-192.png`, `assets/icon-512.png` | favicon/app-icon set | GitHub Pages `<head>`, PWA manifest if one exists | Generated by `logo-design`'s `export_variants.py --web-icons` |
| `assets/mark-black.png`, `assets/mark-white.png` | 512 px raster | Anywhere SVG isn't accepted (e.g. some badge services) | |

## States that actually apply (terminal/web context, not UI states)
| Context | Behaviour | Notes |
| --- | --- | --- |
| Color terminal (truecolor/256) | May show `mark-small` rendered as ANSI art or just the wordmark in `color-brand` | Not implemented yet — no CLI banner command exists |
| `NO_COLOR` set, or non-TTY/piped stdout | Plain text only, no ANSI colour, no mark | Follow the `NO_COLOR` convention already in wide CLI use; `hinge --json` output must never include ANSI either way |
| Dark terminal/dark GitHub theme | Use `mark-white.png`/white lockup, not the black version | GitHub's README renderer doesn't support `prefers-color-scheme` swaps in plain Markdown — if a theme-aware logo is wanted later, use a `<picture>`/two-image `prefers-color-scheme` trick in the rendered HTML (GitHub strips `<picture>` from READMEs, so this needs the GitHub `#gh-dark-mode-only` / `#gh-light-mode-only` anchor convention instead) |
| Light terminal/light GitHub theme | Use `mark-black.png`/`assets/mark.svg` black | Default |

## File selection by size (replaces "responsive breakpoints" — there is no layout to break)
| Target | File |
| --- | --- |
| Browser tab favicon (16–32 px) | `favicon.ico` (already bundles the small-size cut) |
| App/PWA icon (192–512 px) | `icon-192.png` / `icon-512.png` |
| README header | `assets/lockup.svg` |
| Social preview (1280×640) | Build from `assets/lockup.svg` centred on a `color-ink` or `color-brand` field — not generated in this pass |

## Edge cases
- **Below 24 px**: always `mark-small.svg`, never a scaled-down `mark.svg` — the pin hole fills in and reads as a rendering bug otherwise.
- **No SVG support** (some badge/shield renderers): fall back to the 512 px PNGs, not a re-drawn version.
- **Monochrome-only contexts** (e.g. printed packing slips, which don't currently exist for this project): the black mark on white is the only tested 1-colour pairing.

## Accessibility
- Contrast ratios checked: black (`#111111`) on white = 18.9:1, white on `#2563EB` = 5.2:1, white on `#111111` = 18.9:1 — all clear WCAG AA for graphical objects (≥3:1).
- `assets/mark.svg`, `assets/mark-small.svg` and `favicon.svg` each carry a `<title>hinge-cli</title>` for screen readers; if embedded inline in HTML, pair with `role="img"` and that same text as `aria-label`, since an SVG `<title>` alone isn't reliably announced when inlined.
- No motion/animation exists or is planned for this mark — omitted rather than invented.
